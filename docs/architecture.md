# 架构方案：poge_ai

> 状态：研究提案（Draft），配套一个可运行的工程基线（`src/poge_ai/`）。
> 本文描述目标架构与可检验假设，不表示相应模块已经实现或已证明有效。
> 历史版本见 `docs/archive/`，其中 `03_normalized_proposal_v0.4.md` 是最初的中文提案原文。

## 1. 目标与非目标

### 目标

构建一种能够在有限本地算力下，通过记忆管理、工具执行、外部资源与异构评估完成复杂任务的智能系统。核心价值不是单纯压缩模型参数，而是优化系统整体的质量、成本、延迟、可靠性和可审计性。

### 非目标

- 不预设必须使用某一种 Transformer 变体。
- 不把“所有记忆操作都必须可微”设为不可更改的教条；可微、离散和混合机制应通过实验比较。
- 不假设互联网永远可用或天然可信。
- 不假设所有任务都应调用工具，或所有外部模型都值得信任。
- 不把端侧小模型当作最终规模边界。

## 2. 核心模块

### 2.1 决策核心

负责理解任务、估计自身能力与不确定性，并选择动作路径。可由 Transformer 或其他序列模型实现。需要输出可记录的动作决策及其置信度/依据摘要。

### 2.2 记忆系统

研究可寻址的状态单元及其生命周期：

- 写入：判断新信息是否值得保存；
- 读取：按任务、语义、时间和来源召回；
- 更新：合并、修订或标记冲突；
- 遗忘：在保留恢复能力的前提下释放低价值内容；
- 巩固：从多条事件中提炼稳定经验；
- 回顾：在任务需要或不确定性升高时重新检查历史信息。

记忆建议分为：
1. 工作记忆：当前任务短期状态；
2. 情景记忆：事件、交互、执行轨迹与来源；
3. 语义记忆：经验证的稳定事实、规则和抽象经验。

每条记忆应尽可能包含来源、时间、置信度、适用范围、访问权限和版本信息。原始材料与压缩摘要应能建立关联，避免压缩后无法追溯。

工程实现（`src/poge_ai/memory.py`）目前用 SQLite 落实这套字段：`kind / content / source / source_ref / confidence / importance / tags / status / supersedes_id`，并提供 `write / search / update / forget / consolidate / stats`。这是**非神经**的可解释基线，不是提案中的可微记忆槽。

一个已经暴露的具体问题：agent 把自己的回答写进记忆后，下一次检索会把它当作独立证据召回，形成回音室。基线用 `exclude_sources=("agent",)` 先绕开它（自生成内容照常留档，但不参与召回）。这只是遮蔽问题，不是解决——自我生成内容的可信度加权本身是一个待做的实验。

### 2.3 工具动作系统

将工具调用视为受约束的动作，而不是普通文本生成。执行链至少包括：

1. 工具发现与能力描述；
2. 权限检查与策略判定；
3. 参数生成和 schema 校验；
4. 沙箱/隔离环境执行；
5. 返回值校验；
6. 结果记录与必要的记忆写入；
7. 超时、重试、回滚和人工确认策略。

外部工具默认最小权限。涉及不可逆外部操作时，应设置人工确认。

工程实现（`src/poge_ai/tools.py`）目前提供：声明式参数校验、`read/write/external` 副作用分级（默认只允许只读）、路径囚笼（文件类工具不能越出工作根目录）、调用预算与审计记录。

### 2.4 异构评审与教师系统

评审来源可以包括不同模型、规则系统、单元测试、数据库查询、模拟器和真实环境反馈。系统需要记录：

- 评审者身份与版本；
- 任务类型和历史表现；
- 与其他评审者的相关性；
- 评审成本、延迟和失败率；
- 最终裁决依据及未解决分歧。

教师模型用于提供示范、提出反例和辅助诊断，不应成为唯一真值来源。可验证任务优先采用确定性校验或环境结果。

### 2.5 分层硬件与存储

一种待验证的映射方式：

| 层 | 候选载体 | 职责 |
|---|---|---|
| 热认知 | GPU/NPU 显存 | 模型权重、当前激活、短期工作状态 |
| 调度 | CPU 内存 | 路由、索引、队列、缓存元数据 |
| 本地长期存储 | SSD/HDD | 原始资料、执行轨迹、压缩记忆、离线工具 |
| 远端资源 | 网络服务/互联网 | 外部知识、远端模型、在线工具与数据源 |

这不是固定的物理绑定。数据复制、索引、网络读取和一致性维护都有成本，应在实验中计入。

## 3. 动作路由

每个任务在以下路径中选择，可组合执行：

- **内部推理/生成**：模型能以足够可靠性直接完成；
- **记忆访问**：需要个人历史、任务状态或已积累经验；
- **工具执行**：需要精确计算、实时数据、程序运行或外部动作；
- **委派评审**：任务不确定性高、后果重要或需要多视角验证。

路由策略需比较准确率、成本、延迟、工具失败率和过度调用率。不能只用模型自报置信度作为决策依据。

工程实现（`src/poge_ai/router.py`）目前是一个显式规则基线：把任务分解为可观测信号（是否含算术、是否要求实时数据、是否引用历史、是否存在记忆命中），再加权得出动作与置信度。规则基线的作用是提供“可被击败的对照组”，而不是声称已经解决问题。

## 4. 训练与进化

建议拆分为可独立验证的环节：

1. 基础模型冷启动；
2. 记忆动作示范与监督；
3. 工具选择与参数生成训练；
4. 过程轨迹评估；
5. 环境反馈与可验证奖励；
6. 记忆整理与持续更新；
7. 安全回归测试。

训练数据必须记录来源、许可、个人信息处理方式和可撤回要求。在线数据不应未经筛选直接进入训练或长期记忆。

## 5. 安全与可靠性原则

- 最小权限、工具白名单、执行沙箱；
- 远端内容视为不可信输入，防范提示注入；
- 记忆写入可追溯、可纠错、可撤销；
- 重要操作保留审计日志；
- 隐私数据默认本地处理，跨网络传输前进行授权与最小化；
- 评审者不可仅凭多数票决定高风险事实；
- 自动发现工具不等于自动授权工具；
- 对断网、服务失效、缓存过期和模型不可用设计降级路径。

## 6. 关键待验证假设

| ID | 假设 | 反证/失败条件 |
|---|---|---|
| H1 | 可管理记忆状态能提升长程任务表现 | 相比强 RAG/上下文基线无显著提升，或错误遗忘更严重 |
| H2 | 记忆内容与热状态分层能降低推理资源成本 | 索引、IO、检索和同步开销抵消收益 |
| H3 | 显式动作路由能改善任务成本效益 | 路由错误、延迟或工具失败导致整体退化 |
| H4 | 异构评审能提升可靠性 | 评审相关性高，或成本高于收益 |
| H5 | 过程监督能改善记忆与工具动作 | 监督信号噪声大、过拟合教师或训练不稳定 |
| H6 | 架构能跨模型规模迁移 | 机制只在特定规模/任务上有效 |

## 7. 成功标准

项目不以单一 benchmark 分数定义成功。至少报告：

- 任务成功率与错误严重度；
- 长程记忆召回率、误召回率、错误遗忘率；
- 工具选择准确率、参数正确率、失败恢复率；
- 每任务 token、GPU/CPU 时间、IO、网络流量和货币成本；
- p50/p95 延迟；
- 隐私泄露与权限越界测试结果；
- 与基线相比的消融结果和置信区间。

## 8. 代码与文档的对应关系

| 文档概念 | 工程对应 |
|---|---|
| 工作/情景/语义记忆 | `memory.py` 的 `kind` 字段与检索过滤 |
| 遗忘与撤销 | `MemoryStore.forget(mode="archive"\|"revoke")` |
| 记忆巩固 | `MemoryStore.consolidate()` |
| 动作路由 | `router.py` 的 `RuleRouter.decide()` |
| 工具权限与沙箱 | `tools.py` 的 `ToolPolicy` 与 `PathGuard` |
| 过程审计 | `trace.py` 的 JSONL 轨迹与脱敏 |
| 端到端基线 | `agent.py` 的 `Agent.run()` |

这张表只说明基线原型覆盖了哪些机制位，不代表任何机制已被证明优于替代方案。
