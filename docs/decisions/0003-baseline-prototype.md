# ADR 0003：MVP-1 基线原型的实现边界

- 状态：Accepted
- 日期：2026-11-13

## 背景

仓库从“纯文档”变成“文档 + 可运行代码”时，需要明确代码覆盖什么、不覆盖什么。否则读者会把 SQLite 记忆误当成提案里的可微记忆槽，把规则路由误当成已解决的路由问题。

## 决策

`src/poge_ai/` 只实现 MVP-1（普通组件基线）：

1. `memory.py`：SQLite 记忆存储。三种记忆类型、来源与置信度字段、归档/撤销、巩固合并、关键词检索。**非神经、非可微、非向量检索**。
2. `router.py`：显式规则路由。输出 `internal / memory / tool / review` 四种动作与置信度。**不是学习得到的策略**。
3. `tools.py`：声明式工具注册表。参数校验、副作用分级、默认只读、路径囚笼、审计记录。**没有进程级沙箱，没有网络隔离**。
4. `trace.py`：JSONL 轨迹记录，带敏感字段脱敏。
5. `planner.py`：可插拔生成后端。默认 `OfflinePlanner` 为确定性模板实现，不得用于评估质量。
6. `agent.py`：把上述组件串成一次可审计的执行。

明确不做：训练、模型结构改动、向量数据库、真实工具生态接入、多模型评审、网络爬取。

## 后果

- 优点：所有组件零第三方依赖、可在无 GPU 无网络的机器上测试；提供可被击败的对照。
- 代价：默认配置下的“回答质量”没有意义，任何质量结论都必须接入真实 Planner 后重新测量。
- 复审条件：出现第一个接入真实模型的评测报告后，重新定义基线范围。
