# 相关工作与现成组件

> 本文件是 `docs/archive/04_existing_solutions_survey.md`（2026-11 的一次检索记录）的归一化整理。
> **重要：以下条目来自检索摘要，尚未逐条回到原文复核。** 时间、版本号、参数规模等细节在使用或引用前必须核对原始来源，否则视为未经证实的线索。

## 结论摘要

- 未发现与完整设想一一对应的现成一体化方案。
- 但设想中拆出的每个组件，都能在公开论文或开源项目中找到成熟实现。
- 真正的空白在于“把可写记忆门控、原生工具路由、分层硬件调度、异构评委生态整合为一个可运行系统”的工程整合，而不是单点发明。

## 一、原生可写记忆（直接改模型内部）

| 方案 | 与本项目的关系 | 需要注意 |
|---|---|---|
| Memory Transformer（2020 系列工作） | 原生定义记忆写入/读取/处理的源头原型 | 无主动遗忘门、无巩固、无分层 |
| 记忆增强的大参数开源基座（检索记录中称 “MemT”，含 36B / 288B 版本） | 与“记忆内生、与注意力并行”方向最接近 | 细节未经复核；最小尺寸仍远大于端侧目标 |
| 持久化状态引擎类开源组件 | 可复用的本地状态存储与更新接口 | 需核对维护状态与许可 |

## 二、状态空间 / 线性循环路线

- **RWKV**：推理时生成独立可编辑 State，可落盘、可手动修改，自带可训练遗忘权重，CPU 推理友好。缺口是没有显式可寻址记忆槽。
- **Mamba（选择性 SSM）**：固定大小循环状态，无显式 KV 缓存，线性复杂度。缺口是状态不可解释、精确召回弱。
- **面向关联回忆的 SSM 变体**（检索记录中称 “Longhorn”）：带显式遗忘控制，长程关联召回更优。

对本项目的意义：如果实验证明固定容量状态的召回下限不可接受，就需要回到“少量注意力 + 可寻址槽”的混合方案。

## 三、OS 级分层记忆

- **Letta（原 MemGPT）**：把 LLM 当 CPU、上下文当 RAM、外部存储当磁盘，做虚拟内存式分页；三级记忆（核心/召回/归档）。与本项目分层思路一致，但记忆操作是函数调用，不是层内门控。
- **Mem0 / Zep（Graphiti）**：生产级多层实体记忆与双时序知识图谱，可复用结构化存储与实体合并逻辑。
- **低位宽持久化 KV 缓存**（边缘设备方向）：把量化 KV 存磁盘、按需热加载，是“内容在磁盘、GPU 只装激活特征”的直接工程组件。

## 四、小模型原生工具调用

- **TinyAgent / LLMCompiler 路线**：面向边缘端的函数调用框架，提供较小参数规模。
- **Gorilla / OpenFunctions**：零样本 API 调用、AST 指标抑制工具幻觉、工具库可检索更新、配套执行沙箱。
- **ToolLLM（ToolLLaMA）**：大规模真实 API 覆盖，强调分布外工具泛化。
- **极简 Agent 框架**：确定性状态机 + LLM 只做推理，代码量小，可在低端设备运行。

## 五、异构调度、评委仲裁与公开蒸馏

- **自进化多智能体路由**（检索记录中称 “EvoRouter”）：在线策略蒸馏做模型选择与成本-质量平衡。
- **LLM Council 类框架**（llm-council-core / llm-panel / SWARM）：评委并行作答 → 匿名互评 → 主席仲裁；厂商无关，可接本地 Ollama。
- **裁判框架**（JudgeArena / Verdict）：可插拔裁判与可追溯评审日志，适合建信用分体系。
- **多智能体协议蒸馏**（AgentArk / MAPD）：把多步协作内化进单模型；异构蒸馏处理格式鸿沟。
- **分布式 Agent RL 训练框架**（AgentJet）：长周期、无人值守训练。

## 六、CPU-GPU 异构协同与边缘部署

- **统一内存架构下的跨层推理系统**（检索记录中称 “EdgeAgent”）：CPU/GPU 零拷贝、动态算力预算。
- **CPU + 核显 + NPU 自动分层**（检索记录中称 “Intel Agent Box + ZimaOS”）：MoE 激活参数放独显、非激活参数放内存。
- **WebGPU / WASM 边缘 Agent**：浏览器端 IndexedDB 做缓存，无需本地安装。

## 七、流式持续学习与在线进化

- **面向小模型的持续学习框架**：推理时学习新文档，内置多种持续学习策略。
- **“睡眠巩固”式后台整理**：清醒阶段接收数据、睡眠阶段后台巩固，与本项目“后台异步整理记忆”一致。
- **在线漂移检测**：用大模型做无任务在线学习的分布漂移检测。

## 八、与完整设想的四个差距

1. 原生记忆基座的最小尺寸仍远离端侧 1~7B 目标；
2. 多数记忆方案停留在系统函数层，没有全可微擦写门控；
3. 工具调用仍依赖 SFT 数据，未做到预训练阶段的三通道路由；
4. 评委仲裁与端侧训练分离，没有打通门控端到端监督。

## 九、最小原型路径（本研究采用的保守版本）

1. 底座：现成小模型（先不训练，先用可插拔 Planner 验证系统）；
2. 记忆层：可解释的 SQLite 记忆 schema + 分页/归档/撤销（**已实现**）；
3. 工具层：声明式工具注册 + 参数校验 + 路径囚笼（**已实现**）；
4. 路由层：显式规则基线（**已实现**，作为对照）；
5. 评审层：确定性校验器优先（**未实现**）；
6. 训练：待基线与评测协议稳定后再启动。

这个顺序与 `docs/research_agenda.md` 的 MVP 划分一致。原始设想中的“先移植记忆注意力、再做分布式 RL”被显式推迟，理由见 ADR 0001。
