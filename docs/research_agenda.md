# 研究议程与 MVP 路线

## 原则

先建立可运行的普通系统作为对照，再逐项替换机制。不要一开始就同时开发新模型架构、记忆引擎、调度系统、教师池和分布式平台，否则无法判断收益来自哪里。

## MVP-0：术语与评测协议

状态：部分完成。

交付：
- 明确工作记忆、情景记忆、语义记忆的边界（见 `terminology.md`）；
- 选定 2–3 类长程任务（待补：目前只有示例任务，未固定数据集）；
- 固定数据集版本、基线模型、硬件和测量方法（待补）；
- 定义隐私与工具安全边界（见 `architecture.md` 第 5 节与 `SECURITY.md`）。

## MVP-1：传统组件基线

状态：已实现最小版本（`src/poge_ai/`）。

交付：
- 一个现成模型（当前为可插拔 `Planner`，默认离线确定性实现）；
- 一个本地 SQLite 记忆库（`memory.py`）；
- 一个简单检索接口（关键词 + 元数据排序，非向量检索）；
- 两三个只读或沙箱工具（`calc`、`now`、`read_text`、`list_dir`）；
- 统一 trace 日志（`trace.py`，JSONL + 脱敏）。

目的：获得可比较的质量、成本和延迟数据。

尚未完成：真实的模型接入评测、数据集、基线对照数字。

## MVP-2：可管理记忆

先做非神经、可解释的记忆操作作为工程基线：
- 记忆记录 schema（已实现）；
- 价值/时效/来源元数据（已实现字段，尚无自动评分策略）；
- 更新、冲突标记、归档与撤销（更新/归档/撤销已实现，冲突标记未实现）；
- 记忆召回评测集（待补）。

再比较学习式门控、向量检索、规则策略和混合策略。不要把“可微”当成优越性的替代证据。

## MVP-3：动作路由

比较：
- 固定规则路由（已实现，作为对照）；
- 模型自判路由（未实现）；
- 模型判断 + 外部校验（未实现）；
- 成本/风险感知路由（未实现）。

报告错误调用、漏调用、无效调用、总成本和端到端延迟。

## MVP-4：异构评审

建立评审者注册表与信用记录。优先加入确定性校验器和环境反馈，再逐步增加模型评审。对模型间相关性做测量，不以简单多数票作为默认裁决机制。

## MVP-5：学习式原生记忆

只有在基线与数据集稳定后，再研究：
- 可寻址记忆槽；
- 写入/更新/遗忘门；
- 主动回顾查询；
- 记忆压缩与恢复；
- 与主干网络联合训练。

## 主要实验问题

1. 记忆容量固定时，性能如何随任务长度和信息密度变化？
2. 遗忘策略如何处理“当前低价值、未来关键”的信息？
3. 记忆压缩后能否恢复原始证据与上下文？
4. 模型何时应回顾，何时应调用工具，何时应直接回答？
5. 异构评审的收益是否超过 API 成本与延迟？
6. 网络不可用时，系统能否安全降级？
7. 同样任务质量下，系统总成本是否低于强基线？

## 发布门槛

每次发布应附：
- 代码版本与配置；
- 数据来源与许可；
- 环境和硬件；
- 完整评测脚本；
- 基线对比；
- 失败案例；
- 已知限制与安全说明。

当前 `0.2.0` 版本只满足“代码版本与配置”“已知限制与安全说明”两项，其余待补。
