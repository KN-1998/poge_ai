# 现有适配方案检索报告
> 检索时间：2026 年 11 月，覆盖原生记忆、状态空间模型、工具调用、多模型仲裁、硬件协同、持续学习六大方向，全部为公开可查的论文、开源项目或可复用框架。

## 总览结论
**不存在 100% 匹配完整设想的一体化现成方案，但架构所需的每一个独立组件，都已经有成熟开源实现，且 2026 年 10 月刚发布的 MemT 已经走到「原生内生记忆」这一最核心的底层改造阶段，不需要从零发明架构。**
当前行业的空白点，恰恰是把「可写记忆门控、原生工具路由、四层硬件分层、异构评委生态」整合为一个端侧小模型的完整体系，所有零部件均已备齐，只缺系统级整合。

---

## 一、原生可写记忆底层架构（匹配度最高，直接修改 Transformer 内部）
这类方案把记忆做进模型计算图，而非外挂数据库，和我们「动底层、不做外部补丁」的要求完全一致。

### 1. MemT 1.0（2026.10 上海团队，全开源）
- 核心能力：
  - 包含 36B 参数 Nano 版、288B 参数 Flash 版，是当前行业最大的开源记忆原生基座；
  - 在 Transformer 内部嵌入持久化记忆模块，记忆注意力与原自注意力并行计算；
  - 历史信息编码为动态可更新的内部记忆状态，支持跨任务留存、召回和递归自我改进；
  - 权重在 GitHub、HuggingFace、ModelScope 全开放。
- 匹配点：完全对应「静态 KV 替换为可写记忆槽、记忆内生、与注意力并行」的核心设计。
- 差距：当前公开资料未明确可擦除门控、分层记忆、隐式回顾的具体实现；最小 36B 参数仍大于端侧 1~7B 的目标。
- 可复用部分：记忆注意力的算子设计、持久化状态更新逻辑，可直接裁剪移植到小模型。

### 2. Memory Transformer（2020 经典论文，技术原型）
- 核心能力：原生定义四类记忆操作：序列更新、记忆写入、记忆读取、记忆内部处理，是所有记忆增强 Transformer 的源头原型。
- 匹配点：从注意力层原生拆分读写操作，而非外部函数调用。
- 差距：无主动遗忘门、无巩固机制、无分层设计，属于基础验证版本。
- 可复用部分：读写注意力的基础数学框架。

### 3. Engine Engine（2026，PyPI 开源组件）
- 核心能力：持久化收缩连续状态引擎，提供可落地的状态存储和更新接口。
- 可复用部分：记忆状态的本地持久化、磁盘读写层实现。

## 二、状态空间/线性循环路线（固定容量、CPU 友好，天然无注意力稀释）
这类架构抛弃全量 KV 缓存，用固定大小状态承载记忆，线性复杂度、天生适合 CPU 和端侧，是小核心的备选底座。

### 1. RWKV
- 核心能力：
  - 类 RNN 循环架构，推理时生成独立可编辑的 State 文件，可直接存磁盘、按需加载、手动修改；
  - 自带可训练的遗忘权重，状态持续动态更新，无 Softmax 全量归一化，不会随长度稀释；
  - 纯 CPU 推理速度快，量化友好，生态完全开源。
- 匹配点：对应「可写可擦、固定容量、GPU 不存内容、CPU 调度状态」的硬件分工。
- 差距：没有显式可寻址记忆槽，记忆为隐式压缩，无法精准定向召回特定旧信息，需要搭配少量注意力补全。

### 2. Mamba（选择性 SSM）
- 核心能力：固定大小循环状态，输入相关的动态离散化更新，完全取消显式 KV 缓存，线性推理复杂度。
- 匹配点：动态门控、无显存膨胀、长序列无衰减。
- 差距：隐式状态不可解释，无法主动触发回顾，精确关联召回弱于 Transformer。

### 3. Longhorn
- 核心能力：面向关联回忆优化的 SSM，样本效率比 Mamba 高 1.8 倍，支持 16 倍训练长度外推，带显式遗忘控制。
- 可复用部分：长程关联召回的状态更新规则。

## 三、OS 级分层记忆（系统层实现，对应四层存储分工）
这类方案不修改张量计算图，而是在操作系统/框架层做记忆分页、调度，是架构中「CPU+磁盘层」的现成实现，不需要重写。

### 1. Letta（原 MemGPT）
- 核心能力：
  - 把 LLM 类比为 CPU，上下文窗口作为 RAM，外部存储作为磁盘，实现虚拟内存分页；
  - 三级记忆：核心内存（常驻上下文）、召回记忆（历史检索）、归档记忆（大容量磁盘持久化）；
  - 模型主动通过内置函数执行记忆换入换出，自带心跳和调度逻辑。
- 匹配点：完全对应「GPU 热数据-CPU 调度-磁盘归档」的分层思路。
- 差距：记忆操作通过函数调用实现，不是层内可微门控，属于系统层而非模型底层。

### 2. Mem0、Zep（Graphiti）
- Mem0：生产级跨模型多层实体记忆，可对接任意框架；
- Zep：双时序知识图谱记忆，擅长时间线和关系建模。
- 可复用部分：长期记忆的结构化存储、实体合并逻辑。

### 3. 持久化 Q4 KV 缓存（2026 边缘设备论文）
- 核心能力：4bit 量化 KV 直接存磁盘，按需热加载，同等显存下可承载的记忆容量提升 75~111 倍，质量损失极小。
- 匹配点：直接落地「内容存磁盘、GPU 只装激活特征」的设计，是端侧记忆的关键工程组件。

## 四、小模型原生工具调用
### 1. TinyAgent（边缘端函数调用框架）
- 核心能力：专门为端侧设计，提供 1.1B、7B 两个尺寸，基于 LLMCompiler 实现端到端函数调用，配套专用高质量训练集，是边缘 Agent 的标准方案。
- 匹配点：小参数、本地工具调用、面向设备控制。

### 2. Gorilla / OpenFunctions（伯克利）
- 核心能力：
  - 支持零样本 API 调用，用 AST 指标抑制工具幻觉；
  - 工具库可通过检索更新，新 API 不需要重新训练模型；
  - 配套 GoEx 执行沙箱，带权限控制、撤销、故障隔离。
- 匹配点：对应「零样本适配新工具、不需要每个工具单独 SFT」的要求。
- 可复用部分：工具语义编码、执行沙箱、防幻觉机制。

### 3. ToolLLM（ToolLLaMA）
- 核心能力：覆盖 16000+ 真实 API，分布外工具泛化能力强，7B 尺寸即可达到闭源模型工具调用水平。

### 4. 超轻量 Micro-Agent / agent-mini
- 核心能力：4B/9B 小模型本地优先，整体代码约 3000 行，无重型框架，采用「确定性状态机 + LLM 只做推理」的模式，最小实现仅 142KB，可在低端手机、嵌入式系统运行。
- 匹配点：极简、低资源、CPU 协同，适合快速原型验证。

## 五、异构调度、评委仲裁与公开蒸馏
完整对应「统御调度官+动态评委池+公开蒸馏」的生态设计，全部有现成开源实现。

### 1. EvoRouter（2026.10 最新论文，开源）
- 核心能力：
  - 自进化多智能体路由框架，基于在线策略蒸馏；
  - 准确率比传统路由高 7.23%，同时推理算力成本降低 50.95%；
  - 自带模型动态选择、成本-质量平衡逻辑。
- 匹配度：和中央调度官的核心逻辑几乎完全一致，是调度层的首选基础框架。

### 2. LLM Council 类框架（llm-council-core、llm-panel、SWARM）
- 核心能力：
  - 厂商无关，支持任意闭源、开源、本地 Ollama 模型接入评委池；
  - 标准三阶段协议：评委并行独立作答→匿名互评/辩护→主席仲裁合成最终结果；
  - 自带历史评审记录、召回率校验。
- 匹配点：完整实现异构评委、交叉校验、匿名评审，直接支持 Claude 作为高权重主席。

### 3. JudgeArena、Verdict
- 核心能力：统一可插拔裁判框架，支持裁判时计算扩展，所有评审日志可追溯，方便做评委信用分体系。

### 4. AgentArk、MAPD（多智能体协议蒸馏）
- AgentArk：把多智能体交互能力蒸馏进单个小模型，将显式多步协作内化到权重；
- MAPD：用结构化协议做异构蒸馏，自动处理证据检索、失败修复，解决不同模型间的格式鸿沟。
- 匹配点：对应「光明正大公开蒸馏、把多教师能力内化给学生」的训练流程。

### 5. AgentJet
- 核心能力：分布式集群强化学习训练框架，兼容所有主流 Agent 协议，支持跨天长周期训练，不需要人工持续干预。

## 六、CPU-GPU 异构协同与边缘部署
### 1. EdgeAgent（2026 论文）
- 核心能力：面向统一内存架构的跨层推理系统，支持 CPU/GPU 零拷贝张量并行，动态分配计算预算，同时打满两类硬件。

### 2. Intel Agent Box + ZimaOS
- 核心能力：自动识别 CPU、GPU、NPU 三类算力，MoE 激活参数放独显、非激活参数放核显/内存，硬件不变的情况下推理速度提升 3~4 倍，内存利用率 90% 以上。
- 匹配点：完美对应「GPU 只跑激活特征、其余放 CPU/内存」的分工，国产 x86 硬件可直接适配。

### 3. CPU-GPU 协同量化方案、WebGPU/WASM 边缘 Agent
- 全量参数存 CPU 大内存，GPU 只加载当前激活层；
- 浏览器端用 IndexedDB 做磁盘缓存，小控制器流式调用工具，无需本地安装。

## 七、流式持续学习与在线进化
### 1. continual-learning-slm
- 核心能力：基于 1.5B 小模型，推理时实时学习新文档，内置五种持续学习策略，无灾难性遗忘。

### 2. Google Sleep 框架
- 核心能力：模拟生物睡眠机制，「清醒阶段」接收流式数据，「睡眠阶段」后台做知识巩固，不需要保留旧训练数据，正好对应我们「后台异步整理记忆」的设计。

### 3. LargeMonitor
- 核心能力：用大模型做无任务在线学习的漂移检测，自动识别新场景、触发适配，支持完全流式的互联网原生训练。

## 八、整体差距与落地路径
### 当前生态和完整设想的四个核心差距
1. 原生记忆模型最小尺寸仍为 36B，缺少 1~7B 级端侧记忆原生小模型；
2. 绝大多数记忆方案停留在系统函数层，没有实现全可微的擦写门控；
3. 工具调用仍依赖 SFT 数据，未做到预训练原生三通道路由；
4. 评委仲裁框架和模型端侧训练是分离的，没有打通门控端到端监督。

### 最小原型快速搭建路径（不需要从零训练）
1. 底座：RWKV-7 / 7B 级 Qwen 小模型，保证 CPU 友好和量化能力；
2. 记忆层：移植 MemT 记忆注意力逻辑 + MemGPT 分页调度 + Q4 磁盘 KV 缓存；
3. 工具层：集成 Gorilla OpenFunctions + 微型状态机，实现零样本工具调用；
4. 云端调度：EvoRouter + llm-council，冷启动阶段接入 Claude 作为高权重仲裁；
5. 训练：用 AgentJet 做分布式 RL，基于公开互联网流式数据做门控微调，全程开源留痕。

### 现实判断
这套方案之所以「贫穷但充满希望」，正是因为它不需要等待下一代芯片、不需要万卡集群，所有技术组件都已在 2025~2026 年集中出现，只需要做系统整合和端侧裁剪，即可落地完整设计。
